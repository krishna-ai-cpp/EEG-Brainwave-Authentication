# CNN inference benchmark

The recorded results compare the original root Keras CNN with `v2/EEGCNN`. The topology is the same, but independently initialized weights are not numerically identical. These are untrained architecture candidates, not a held-out authentication evaluation.

## Measurements

Each entry is the median of three fresh-process run medians. Inputs were float32 prepared EEG windows with 64 channels and 320 time samples (2 seconds at 160 Hz). Each run used 25 warmups and 100 timed responses. Framework order alternated.

| Setting | Batch | TensorFlow CPU | PyTorch CPU | PyTorch RTX 3050 GPU |
|---|---:|---:|---:|---:|
| Initial, four CPU threads | 1 | 14.698 ms | 0.846 ms | 0.586 ms |
| Initial, four CPU threads | 32 | 17.528 ms | 1.627 ms | 0.995 ms |
| Later four-thread repeat | 1 | 9.870 ms | 0.786 ms | 0.604 ms |
| Later four-thread repeat | 32 | 14.142 ms | 1.530 ms | 0.946 ms |
| Single-thread setting | 1 | 12.165 ms | 0.317 ms | 0.564 ms |
| Single-thread setting | 32 | 15.536 ms | 4.695 ms | 0.925 ms |

The initial same-CPU single-window ratio was about 17.4x. The later four-thread ratio was 12.6x; the single-thread ratio was 38.4x. The single-thread setting favors small-window CPU latency; larger CPU batches were slower than with four threads. TensorFlow currently detected no GPU, so CPU-to-GPU ratios also reflect different hardware.

TensorFlow 2.21.0 and PyTorch 2.11.0+cu128 were used, with float32 inference and matching CPU thread counts within each comparison. Dropout was disabled and gradients were not recorded. No tracing or compilation optimization was added. TF32 was disabled. Every measured response started with a NumPy input on CPU and ended with a NumPy output on CPU, including tensor conversion, device transfers and GPU synchronization. Imports, model construction, layout preparation, normalization and DataLoader iteration were outside the warmed timer.

**These results do not measure the complete pipeline or Optuna training.** In the earlier fresh-process checks, the supplied three-EDF workflow took 4.993 s for the original and 7.130 s for the rewrite, both stopping at the inherited independent-group guard. A complete six-recording synthetic preprocessing/SVM run took 5.649 s versus 7.429 s. The original imports TensorFlow only for its optional CNN; the rewrite imports PyTorch at startup. SVM and preprocessing statements are preserved and remain CPU work.

The new Optuna step keeps model topology fixed and runs only during training/search. Its six trials are additional offline work. Checkpoints need training normalization for future inference. Nothing here establishes V2 accuracy, faster training, a real-data trained-model speedup, or an end-to-end 17x improvement. System load and settings can change the ratio.

## Reproduce on your own authorized windows

From `v2/`, with the V2 environment active:

```bash
python benchmarks/benchmark_inference.py --framework pytorch --windows /path/to/recording_0_windows.npy --threads 1 --output pytorch_benchmark.json
```

The input file must have shape `(windows, channels, time_samples)`, as generated by preprocessing. If it contains fewer than 32 windows, examples are cycled to form the throughput batch. Use the same window file and thread count for both frameworks. Both CPU and available GPU cases are measured.

To compare TensorFlow, use a separate benchmark environment with TensorFlow 2.21.0, NumPy and the appropriate device dependencies, then run:

```bash
python benchmarks/benchmark_inference.py --framework tensorflow --windows /path/to/recording_0_windows.npy --threads 1 --output tensorflow_benchmark.json
```

The script reads the original Keras layer assignment from `../hello.py`; it does not execute the original interactive workflow. Run three fresh processes per framework and alternate order before comparing medians. Use `--threads 4` to reproduce the earlier thread configuration. GPU access depends on the installed framework build and driver.

Published [results.json](results.json) contains sanitized run medians, versions and settings. Local recording files, biometric arrays, absolute workstation paths and private result directories are not published.
